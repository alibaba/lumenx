# Elicitation Question Patterns

Use these only when the default questions are not specific enough.

## product_definition

- What should this product never be mistaken for?
- If someone only remembers one feeling after using it, what should that feeling be?
- Which part should be a real feature, and which part is only an explanatory metaphor?
- What existing behavior should this product change in the real world?
- What would make this feel generic, even if it is technically correct?

## agent_design

- If this agent only did one thing, what cognitive burden must it remove?
- What is its most dangerous failure mode: asking too much, asking too little, executing too early, or becoming a summary machine?
- Whose behavior should its output change?
- Which existing workflow becomes obsolete or less important if this agent works?

## weekly_review

- What judgment from this week is worth preserving?
- Which moment felt like “there is something here” but remains unnamed?
- If next week could only improve one structural thing, what should it be?

## strategic_tension

- Is this signal more like an opportunity, a risk, a taste rejection, or system debt?
- If we ignore it, what will become more expensive three weeks from now?
- What does this tension require us to stop doing?

## postmortem

- Did this failure expose a tool problem, a workflow problem, or a judgment-placement problem?
- Which question, asked ten minutes earlier, would have prevented the rework?
- Should this lesson become a skill rule, memory rule, test, or checklist?

## taste_alignment

- Do you like the result, the process, the posture, or the worldview behind it?
- What similar thing do you dislike, and what is the difference?
- Should this taste affect topic selection, writing, product design, visual design, or agent behavior?
