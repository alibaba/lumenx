# LumenX 创作旅程与验收场景

公开整理：2026-10-30；行为规格保留自研发快照 `7765f9e816088a88f8489a737ad70eb7211de051`。本文定义必须观察到的行为，不宣布产品测试、浏览器、真实模型或安装包已经通过。当前候选结果见 [台账](EXECUTION-STATUS.md)，功能与测试入口见 [矩阵](TEST-MATRIX.md)。

产品边界由 [契约](PRODUCT-CONTRACT.md) 和 ADR 决定。以下 24 组场景是既定承诺的验收，不是新增 24 项功能；Studio 的生产流程和 Atelier 的探索、判断、分支各自独立。U/I/H/V/E 的含义见测试矩阵。

## Studio：从分集剧本到可继续修改的成片

使用两集原文、一位共享角色和三镜头短片；为候选 A/B 制作可辨认的画面与音轨。验收终点是保存、素材选择、配音归属与实际成片一致，并能重开继续创作。技术可解码与创作者认可分别判断。

| ID | 操作与必须观察到的结果 | 功能映射 / 测试层 |
|---|---|---|
| **SJ-01 普通文字保存** | 修改原文一句话→失焦→离开并重开，不点“提取实体”，新文字仍在；不得触发额外 LLM 解析。保存失败可见，不能仅写控制台或被本地缓存伪装成功。独立 ScriptEditor document 另按 F02 验证 | F01；V/H/E |
| **SJ-02 跨集角色可用** | 提升/合并为同一系列角色后，两集均能读到同一资产；给共享角色绑定音色，两集对白能够实际生成。共享变更与集内覆盖遵循已有明确优先级，既有成片不被自动重做。关联更新失败后重开不得出现半绑定 | F04/F06/F09/F17；I/H/V/E |
| **SJ-03 分镜与参考一致** | 修改镜头顺序/提示词并选参考，保存后重开保持；真实视频请求使用对应的明确参考。Studio 预览图不能被误当用户设置的首帧；缺失或互斥输入在付费前明确反馈 | F10–F13；H/V/E |
| **SJ-04 显式选择受保护** | 给同一镜头生成 A/B，明确选择并锁定 B；A 的迟到完成、刷新和重开不改变选择。未锁定镜头的既有自动选择规则另测，不能为统一 Core 强行改为 Atelier 规则 | F11/F16；I/H/V/E |
| **SJ-05 配音绑定正确视频** | 给 A 配音并应用→选 B→预览与合成均用 B；A 的配音保留来源，但不得冒充 B 的配音。用带 A/B 标记的短片检查实际导出帧，不能只断言 selected ID | F16/F17/F18；I/H/V/E |
| **SJ-06 声音控制真实生效** | 对当前入口宣称支持的 BGM/对白/SFX 控制，分别用可区分音轨和音量测试实际输出；不设置 BGM 也不能使承诺支持的对白音量失效。缺素材/处理失败须明确，不能静默跳过后声称这些设置已应用 | F17/F18；U/I/H/V/E |
| **SJ-07 完整且当前的成片** | 三镜头合成须包含三个正确版本且顺序一致；删掉一个输入文件后明确指出缺失镜头，不能悄悄交付两镜头版本。换 take 或混音后，旧成片仍可保留，但明确不是当前编辑的重新合成结果 | F18/F19；I/H/V/E |
| **SJ-08 重开后继续创作** | 重开读回服务端正式原文、分镜、选择与配音归属；改一处再合成，未改镜头及旧成果仍可解释。旧导出链接不作为“本次修改已导出”的证明 | F01/F09/F16/F18；H/V/E |

## Atelier：从想法到独立轻量成片

从一句想法或自有参考开始，提出草稿、按授权生成、比较候选、记录判断并从指定候选建立分支。挑选三个精确候选编排序列；整个过程不要求 Studio 项目。草稿数不等于授权付费次数，判断、采纳与编排是不同操作。当前视频序列/裁切/MP4 的 UI 子集不等于专业多轨编辑器。

| ID | 操作与必须观察到的结果 | 功能映射 / 测试层 |
|---|---|---|
| **AJ-01 独立创建与重开** | 没有 Studio 项目也能创建想法/参考/草稿，保存、切换项目、重开后仍在；保存失败不能只靠本地画布暂时存在冒充完成 | F24/F25/F29；H/V/E |
| **AJ-02 精确参考保真** | 引用源节点的候选 A，再把源节点采用版本改成 B；目标仍引用 A。引用不会自动采纳或生成；后续请求保持来源及输入角色，删除/不可访问时明确报出 | F28/F29/F30；I/H/V/E |
| **AJ-03 所见批准等于执行** | 同一受支持意图从手工和 Agent 进入服务得到等价参数/参考；入口未支持的字段明确拒绝。批准后改变参考、模型、参数或付费范围，不能偷偷复用旧批准执行新意图 | F30/F36/F37/F38；I/H/V/E |
| **AJ-04 判断、采纳、编排分离** | 给 B 记录 verdict/reason，不改变已采用 A；可把 B 加入序列而不改变 A。刷新后判断、选择、序列三份事实分别保持；Agent v1 不因生成完成自动采纳。实际候选执行范围见台账 | F33/F40；H/V/E |
| **AJ-05 分支不改父成果** | 从 A 建新 draft，来源和可用条件保留，父节点/候选不变且 provider submit 计数为零；编辑分支再生成是新意图，旧失败任务的重试另走原条件 | F34/F35；I/H/V/E |
| **AJ-06 保存与导出一致** | 快速排序/裁切后立即导出，先确认该版序列保存，再冻结同一版导出输入。注入保存失败或 revision 冲突时，反馈错误、保留可恢复编辑，不把另一版序列导出成“已保存当前作品” | F40/F41；H/V/E |
| **AJ-07 失效条目可见可修复** | 已入序列的 take 被软删除或不可用后，其位置显示具体失效原因与修复入口；未修复前导出指向同一条目。不能画面里藏掉一项，导出才因该隐藏项失败；不能自动替换成节点最新 take | F28/F33/F40/F41；H/V/E |
| **AJ-08 导出与历史可解释** | 用带 A/B 标记的短片验证顺序、裁切与精确 candidate；导出开始后修改画布不偷换本次输入。完成历史重开可读；Redo 按历史输入提交并有可达的终态反馈。渲染中退出/重启不得无限“处理中”或冒充成功，已有文件保留并按可确认事实恢复/标中断 | F41；I/H/V/E |

## 两款产品共同验收

| ID | 场景与必须观察到的结果 | 功能映射 / 测试层 |
|---|---|---|
| **CJ-01 相同意图保真** | 只在声明共同支持的能力范围比较 Studio/Atelier/Agent；输入角色、参考、有效参数一致，`0/false` 不丢失，产品预设可见。允许各自 batch/展示/采纳策略不同；不支持输入在付费前明确拒绝 | F11–F14/F20/F21/F30/F36/F37；U/I/H/V |
| **CJ-02 丢响应不重复花费** | 同一请求因响应丢失而重放，即使 catalog 默认已更新，也返回原接纳结果，不新建候选、不重复 submit；相同请求 ID 不同 payload 明确冲突。取消、审批和旧 attempt 竞争不绕过提交前校验 | F11/F16/F35/F37/F38；I/H/E |
| **CJ-03 重试与新生成不同** | 已知失败的重试保留原有效参数/固定媒体；改提示词或采用新默认产生新生成并保留来源。旧记录缺完整快照不得伪造已知条件；可用查询身份仍允许找回原结果 | F11/F15/F30/F34/F35；U/I/H/V |
| **CJ-04 区分排队恢复与原任务查询** | 在提交前后和结果保存边界注入重启。①持久记录证明尚未进入提交阶段：原授权有效、未取消且取得执行所有权时，可继续原任务，禁止重复派发。②已有可靠查询身份：只 query/fetch，submit 计数不增加。③已进入或不能排除提交阶段，而缺 handle、查询环境不明或查询异常：保持待确认，不自动付费重发。找回结果不自动采纳 | F15/F35；I/H/V/E |
| **CJ-05 保存失败与旧窗口** | 磁盘写失败/损坏、关联更新中断、第二写进程、旧页面局部修改分别验证；旧有效数据和已付费媒体保留；无假成功、无静默覆盖。单写者限制不代替同一服务内 revision/字段所有权保护 | F01/F05/F06/F24–F28/F40/F44；U/I/H/V/E |
| **CJ-06 四种入口组合** | 浏览器/正式桌面 × 本机/ECS 均读取所连环境正式状态；切换环境/断线不串写、不误认另一个服务。正式桌面远程模式不启动本地生成后端；关闭窗口不结束非自有服务 | F21/F23/F43/F44；I/V/E；真实包另记 |
| **CJ-07 独立工程复制** | 使用合成项目与媒体复制到另一环境，目标可编辑/播放，源项目不变且不自动同步；不依赖原机器绝对路径，不复制密钥或在途付费执行权。失败不发布半完整工程；不是 Studio↔Atelier 转换 | F42；I/H/V/E |
| **CJ-08 媒体与访问可靠** | 无 OSS 本机仍可使用；远程访问受所连环境权限约束，媒体能播放但内部 JSON/配置不可下载。签名更新不改变媒体内容身份，引用失效不偷换素材；以实际可解码文件验证结果 | F19/F28/F29/F41/F43；I/H/V/E |

## 历史反例定义

下表保留 2026-10-09 旧基线走查的编号及触发条件，方便确认修复没有回退。原源码行号及工作区证据留在来源分支，未随公开候选发布。标题不表示当前仍有此缺陷；修复和当前执行状态不能由这张表推定。

| 编号 | 历史触发条件与影响 | 验收归属 |
|---|---|---|
| **S-R1 原文停在本地缓存** | onChange 已更新 Zustand 文本；onBlur 又比较这个更新后的值，通常相等就返回。普通输入可能没有真正保存，重开被服务端旧文本覆盖 | SJ-01/F01 |
| **S-R2 共享角色的声音查找不完整** | Reconcile 将角色移出本集集合后，界面和分镜还能解析系列角色，音色绑定/逐句与批量 TTS 却只查本集集合，可能报错、跳过或无产物返回 | SJ-02/F09/F17 |
| **S-R3 预览选 B、合成仍用 A 的配音版** | 选择操作不清除旧配音关联；预览检查配音来源 task，merge 却无条件优先旧 dubbed URL | SJ-05/F16–F18 |
| **S-R4 混音设置与执行不一致** | 对白音量只在有效本地 BGM 分支中应用；SFX 音量未进入当前混音命令；缺失 BGM 或混音失败可被跳过 | SJ-06/F17/F18 |
| **S-R5 缺镜头或旧成片仍可能呈现为成功** | merge 跳过缺视频/文件后可交付剩余镜头；改变选择或混音不会让旧 merged URL 自动区分为旧版 | SJ-07/SJ-08/F18/F19 |
| **A-R1 序列保存与导出没有衔接** | hook 有 flush，但 Shell 没传给当前 SequenceStrip；Strip 直接导出本地 entries。它不必然导出旧条目，却可能在正式保存失败时导出成功，重开后时间线与成片不一致 | AJ-06/F40/F41 |
| **A-R2 隐藏失效项仍参与导出** | Shell 的显示 entries 过滤缺失/未完成候选，Strip 的 payload 却遍历原 sequence；用户看到的序列与后端拒绝的输入不同 | AJ-07/F28/F33/F40/F41 |
| **A-R3 能力边界：前端比后端时间线能力窄** | 当前 Strip/客户端只提交视频条目与裁切；后端已有 audio_tracks。没有发现另一份已写好但未挂载的新版 sequence 编辑器；这不自动构成应新增音轨 UI 的缺陷 | CJ-01/F41 |
| **A-R4 完成历史不等于在途恢复与反馈完成** | 导出 job/冻结输入在内存，完成后才记录持久历史；Redo 界面只报已排队，handler 无终态轮询/自动刷新，当前可手动刷新 | AJ-08/F41 |

## 形成真实验证

1. 在测试收集和应用导入之前隔离配置、数据根、网络与供应商预热；复用仓库隔离运行器，不对个人项目试跑。
2. 调用真实生产函数、服务、路由和组件，仅替换外部传输与明确故障；测试内复制业务规则不能替代产品测试。
3. 使用短合成 A/B/C 视频及可区分音轨，以真实 FFmpeg/ffprobe 检查选材、顺序、时长和声音。合成外部传输成功不等于真实供应商成功。
4. 关键链路分别覆盖正常完成、编辑后重开和故障。线程、同进程新 app、正常换进程与异常断电是不同证据；不能互相外推。
5. 记录候选源码、环境、实际命令、用例 ID、通过/失败/跳过及未测边界。浏览器、正式桌面、远程部署与收费模型分别验收。24 个场景 ID 及 44 行矩阵本身都不是执行结果。

不借此增加完整音轨 UI、更多 Agent 自动采纳权限、Studio/Atelier 整项目互转、分享或多人协作。Studio 未锁定镜头的既有自动选择策略与 Atelier 人工采纳规则分别保护。
