## 共同哲学

LumenX 帮助创作者把意图变成可控制、可积累、可交付的视听作品。

- 创作者拥有方向与审美判断。Agent 提议、探索和执行，当前 Atelier v1 的候选采纳仍归用户；生成完成、技术合格与创作者认可分别判断。
- 创作过程值得保留。意图、参考、参数、候选、分支和结果之间的关系应可理解；失败、重试和修改不应无声覆盖过去的成果。
- 自动化必须可控。权限、付费范围和执行内容有明确依据，不能靠黑箱变化替用户作出未授权决定。
- 用户以创作对象组织工作。底层模型、供应商和执行细节由共同能力支持；需要追溯时可以查看，不强迫用户先学习底层工作流图。
- 本机独立运行是基础，远程环境是可选扩展。浏览器/桌面是操作形式，单人/多人是使用范围，均不拿来区分 Studio 与 Atelier。

## 两款产品的划分

| 维度 | Studio | Atelier |
|---|---|---|
| 主要问题 | 已有故事或剧本，怎样有组织地完成生产与交付 | 从想法、图片、参考视频或片段开始，怎样探索方向并形成作品 |
| 核心组织对象 | 项目、系列/分集、剧本、资产、分镜、生产任务 | Seed、计划、草稿、参考、候选、判断、分支、序列 |
| 主体形态 | 按生产阶段组织的工作台，围绕分镜和批量任务推进 | 创作图画布 + Agent 面板 + 轻量序列编排 |
| 主要价值 | 连续性、一致性、复用、批量处理和交付效率 | 多方向探索、参考与来源关系、快速分支、人机协同和审美选择 |
| 独立闭环 | 剧本/项目 → 资产与分镜 → 生成 → 编排 → 导出 | 灵感/素材 → 探索与生成 → 判断/分支 → 序列 → 导出 |
| 复杂度边界 | 不因共用能力而强制把生产流程改为通用无限画布 | 当前轻量成片，不把专业多轨剪辑、底层可编辑执行图或任意插件作为 v1 前提 |

同一个人可以同时使用两者。Studio 的系列生产倾向不意味着现在就实现多人协作；Atelier 的个人探索倾向也不代表它只是试验玩具或只能输出素材。

### 容易误解的重叠

1. 两者都可以生成图像/视频/音频、使用参考、管理结果并导出；这些能力重叠是正常的。区分依据是创作对象、工作流和用户所处阶段，而非强行让某个功能只出现在一款产品。
2. Agent 是 Atelier 的重要特色，但不由此推导 Studio 永远不能有辅助智能能力；也不要求 Atelier 的每个手动操作必须绕经 Agent。
3. Atelier 已有独立成片方向，不是只能给 Studio 提供前期素材。路线图中的 final film 与 v1 的 rough cut 可按“独立轻量成片”理解，不应无依据扩大成专业剪辑器承诺。
4. 两款产品未来可以交接窄范围成果，但既有 v1 路线图明确推迟正式 Studio/Atelier bridge 与整项目同步。本次本机→ECS 的独立复制是同类工程跨环境携带，不是 Studio 项目与 Atelier 画布互转。
5. Core 共用模型、媒体、执行与导出能力，各产品分别拥有自己的创作状态和采纳规则；功能开放范围可以不同，但受支持输入必须保真。

## 本轮验收与长期愿景分开

本轮继续按已确认承诺推进：保护既有功能，落实真实测试覆盖、保存/契约/生成恢复、本地与 ECS 使用、浏览器和桌面双入口、可编辑工程独立复制。未提交分支能力需形成明确集成基线后验证，不靠路线图文字假定已可用。

旧家族路线图还列有私密分享、创作偏好/Canon 记忆、更宽的音频/SFX 能力等目标。这些不等于本轮已经承诺完整交付；具体实现状态和下一阶段范围需分别核对。本文保留它们的路线图身份，不擅自删除，也不把它们悄悄加进架构重构的完成条件。

专业多轨剪辑、工作流/插件市场、跨产品自动同步等在既有 v1 边界外；扩大这些边界属于产品决定。测试映射中的 44 个功能组是验证索引，不是 44 个新增功能的开发承诺。

## 是否继续 grill

当前无需全面重新讨论共同 Core、两个独立产品壳、本机/远程或参数/恢复规则；已有足够依据可以继续安全基础重构。

2026-10-09 的源码走查形成 [24 组行为验收规格](PRODUCT-JOURNEYS.md)。它们继续作为规范；当时的“未运行”不描述后续实现，当前候选运行结果只见台账：

- Studio：已有分集剧本与角色资产 → 完成分镜、参考生成、候选采纳和导出；能看见连续性、生产进度及失败处理。
- Atelier：只有一个想法或参考片段 → 探索多个方向、保留判断与分支、整理序列并独立导出；不要求先创建 Studio 项目。
- 共同能力：相同受支持意图在不同入口保持含义一致，各产品仍保留自己的批量策略、状态和结果采纳方式。

走查确认或细化了 8 处保存、共享角色、取材、声音与导出衔接缺口，以及 1 处前后端能力边界差异；均可按已有原则处理，没有新增必须选择的产品分岔。能力子集差异不自动变成新增功能要求。当前需要落实的是场景回归与实现一致性，不能用文档替代实际创作验证。

以后若发现真正的产品冲突，再一次讨论一个问题。下列变化才值得开启针对性 grill：改变主要创作场景或资源优先级；提高 Agent 自动花费/修改/采纳权限；把轻量编排升级成专业剪辑器；提前纳入分享、多人协作、跨产品同步等承诺。没有此类冲突时，由助手按现有原则处理常规设计与实现选择。
