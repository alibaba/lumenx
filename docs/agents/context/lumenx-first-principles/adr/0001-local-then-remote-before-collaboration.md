# 先打磨单人本地与远程创作，延后多人协作实现

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

LumenX 当前以单人本地创作（A）作为验收目标，近期向单人远程创作（B）演进。多人协作（C）需要在架构与设计中考虑，但暂不实现；先把 A、B 打磨好，再推进 C。

这一取舍将近期投入集中到个人创作者的完整使用过程，同时要求设计评审考虑远程访问与未来共享项目的演进。仅满足 A 而忽视 B、或为当前阶段提前实现完整 C，都不符合本次确认的方向。

## 验收影响

功能与测试清单需区分 A 的验收行为、B 的验收行为及 C 的未来兼容约束，不能将三者混为一个完成状态。具体行为已由 [产品旅程](../PRODUCT-JOURNEYS.md) 与 [测试矩阵](../TEST-MATRIX.md) 细化；实施结果只在 [执行台账](../EXECUTION-STATUS.md) 登记。

## 后续澄清：本轮包含 ECS 远程试用

用户在确认 Q2 时进一步提出：本轮重构完成后，希望把 LumenX 部署到自己的 ECS，并在本机操作试用。因此，本轮先保证 A，并纳入 B 的具体 ECS 部署试用场景；这不等于已经承诺完整远程产品发布或开始实现 C。浏览器/桌面四组合已由 [ADR-0002](0002-local-default-authoritative-project-service.md) 确认，试用验收见计划 P10。

## 后续决定与本记录边界

本记录只定义阶段范围。默认本地与正式状态由 ADR-0002 确认；保留文件存储、单写者、产品状态独立由 [ADR-0006](0006-converge-execution-with-product-owned-state.md) 确认。身份归属、局部字段更新和 revision 冲突检查已在现行 [计划](../REFACTOR-PLAN.md) 规定，为未来协作保留边界但不实现 C。ECS 现场接入和具体鉴权配置到 P7/P10 细化，不是重开 A/B/C 决策的理由。
