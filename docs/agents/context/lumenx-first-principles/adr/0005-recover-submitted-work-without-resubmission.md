# 自动找回已提交任务，恢复查询与重新生成分开

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

LumenX 后端中断不等于供应商任务失败。用户选择把自动找回已提交任务的进度和结果纳入本轮范围：供应商支持查询且已可靠保存任务标识时，重启后查询原任务并取回结果；无法确认时明确显示待确认状态，不自动重新提交付费生成。

相较只提供人工排查，自动查询可减少本地与 ECS 使用中的丢失结果和重复费用风险；代价是必须拆开供应商提交、查询和结果取回，并保存查询所需的任务身份。当前已有部分 provider ID 回调与候选 attempt 保障，但尚未形成完整恢复链路。

## 行为边界

- 恢复查询继续跟踪原任务，不产生新的生成请求，不重新解析 Q8 已固定的有效参数。
- 已知远端任务失败后，用户仍可按原参数发起失败重试；“本地流程中断”“查询超时”“缺少标识”均不足以证明远端失败。
- 提交返回前断开、供应商不支持查询、任务标识未保存等情况保留不确定性。没有供应商幂等保障时，不宣称跨网络提交与本地保存能保证恰好一次计费。
- 查询恢复仍遵守项目归属与执行身份；迟到结果不能覆盖新的执行尝试。取回产物不代替 Atelier 用户的候选判断和采纳。
- 本题没有授权对状态不明的任务重新付费，也没有扩大 Agent 的原批准范围。

## 可观察验收

1. 假供应商已接纳任务，服务重启后查询同一 provider task ID 并保存结果；提交调用计数保持不变。
2. 对处理中、已完成、已失败和查询不明四类回答，状态和前端反馈分别正确；临时查询失败不被误判为生成失败。
3. 缺少可靠标识或供应商不支持查询时，不调用生成方法，明确提示结果尚无法确认。
4. 重复恢复、旧 attempt 返回和存储故障不会覆盖新尝试、吞掉已付费媒体或自动选中候选。

以上是已确认的设计验收方向，不是实现或运行证明。工程顺序按现行计划，供应商能力与测试结果按执行台账登记的适用版本和证据核验。
