# 渐进共用执行协议，保留产品状态与当前部署规模

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

决定采用渐进收敛：复用现有 catalog、adapter 和 Atelier 候选服务，统一输入解析、提交/查询/取回契约、attempt 状态转移与验证规则。Studio、Atelier、Playground 各自拥有产品任务、创作对象和采纳状态；薄存储适配落实相同可靠性规则，不建立第二套任务事实源。

这是助手按用户授权作出的技术选择，不表示用户逐项指定了模块或存储实现。产品目标仍为单人本机使用和近期 ECS 使用，浏览器与桌面均可操作；多人协作仅保留边界。

## 取舍

另一可行方案是先集中持久任务仓库，再迁移产品投影。它有利于统一事务、调度和未来扩展，但当前会先引入历史任务映射、双写切换或停机迁移，还需跨长期分叉保留候选与审批语义。当前没有规模证据要求先承担这次整体迁移。

渐进方案的真正风险是把付费状态协议复制三遍。为此，共享状态转移判断与契约测试，由产品存储承载数据；不允许各入口另写一套重放、提交和恢复规则。未来实际规模或协作承诺超出现状时，再评估集中任务仓库。

## 当前约束与后果

- 暂保留文件存储，一个数据目录只有一个写进程；先统一保存成功语义、故障恢复和版本冲突，再按实际命令处理跨文件一致性。原子替换不等于跨文件事务。
- 接纳和提交协议可靠后才切换真实付费链。查询恢复属于本轮必交付项，不以等待通用任务仓库为由推迟。
- Qoder 未提交增强属于保护证据，待有可纳入的固定提交后逐项集成；当前可先在 main 的隔离基线推进安全组装与测试。
- 本轮正式桌面路径采用现行 `main.py → PyInstaller` 构建，修复并验证它的本地/远程生命周期；Tauri 保留实验状态，不用其开发运行结果代替正式安装包，也不扩大为两套壳同步重写。
- 目录调整随依赖收敛进行，不能以文件移动或体积减少代替功能和故障验证。

验收与回滚按 [重构计划](../REFACTOR-PLAN.md)；前后端测试范围按 [测试映射](../TEST-MATRIX.md)。本记录没有声明源码实施或测试完成。
