# 默认本机独立运行，由所连接的 LumenX 服务管理正式项目状态

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

LumenX 默认可以在用户本机独立运行，不要求另购或部署远程服务器。远程访问是可选扩展；一个项目的正式内容、素材关系与任务记录，由承载该项目的 LumenX 服务管理，浏览器或桌面入口以其确认的状态为准。

本地阶段，服务和项目可位于用户自己的电脑；远程阶段，服务可位于用户部署的机器。这里的服务是一种运行职责，不等同于必须拥有独立物理服务器，也不代表所有用户依赖统一托管的云端 LumenX。

## 取舍

采用一处正式状态，便于一致定义保存确认、任务恢复和未来多端操作。A、B 阶段不以“每台设备独立修改完整副本，随后自动合并”为目标；代价是正式项目操作依赖与所选服务的连接。携带已有项目的语义由 Q5 确认为独立复制。保留已有可恢复草稿/journal 不代表其已成为正式状态，也不新增离线自动合并承诺；具体断线和冲突行为按现行旅程与计划验收。

“一个权威服务”是逻辑归属，不在此限定服务进程数量、数据库或部署技术。调用云端生成模型与 LumenX 的部署位置是两个独立维度。

## 本轮验收方向

- A：没有远程 LumenX 服务器的用户，也能够在本机开展创作。
- B：重构完成后，在用户的 ECS 上部署 LumenX，并从本机实际操作试用。
- Q4 已确认：本轮需要支持携带已有本机项目及其素材、已生成结果，到 ECS 继续创作；不能仅以在 ECS 新建项目完成此项验收。
- 保存、读取与任务状态应围绕所连接服务的正式状态验证，避免用客户端缓存伪装保存成功。

桌面自动启动本机服务是目标体验，仍需修复与测试证明。本记录确认设计与试用方向，不宣称启动、部署或生成链路已经验证。

## Q3 澄清：操作入口与部署位置相互独立

用户明确要求浏览器和桌面应用都可以作为操作入口，由用户任意选择。因此本轮 ECS 试用必须覆盖两种入口；不采用将桌面远程连接推迟到后续阶段的初始建议。

| 创作环境 | 浏览器入口 | 桌面入口 |
|---|---|---|
| 本机 LumenX | 纳入验收 | 纳入验收 |
| ECS 上的 LumenX | 纳入验收 | 纳入验收 |

连接同一创作环境时，两个入口操作该环境管理的同一批项目，遵循相同业务规则。两个入口的存在不引入两套正式项目状态；切换到另一处 LumenX 服务涉及环境和数据归属，需要明确区分。

对应测试至少需要验证四种组合的连接与核心操作、同一项目在不同入口加载后的正式状态一致，以及连接失败或切换环境时不会将操作发送到错误的服务。缓存/凭据/正式桌面生命周期的实施边界已写入 [计划 P7/P10](../REFACTOR-PLAN.md#execution-order)；实际执行情况见 [台账](../EXECUTION-STATUS.md)。

## 后续决定

两种入口均已确认。保存和环境所有权由 [ADR-0006](0006-converge-execution-with-product-owned-state.md) 及计划细化；生成默认/快照与恢复分别由 ADR-0004/0005 确认；项目携带语义见下面 Q5。已结束逐项访谈，按现行计划实施；网络接入和 ECS 现场配置留待对应阶段取得事实。

## Q5 澄清：携带产生独立项目副本

用户选择“复制为独立项目”。原项目继续保留并可编辑，ECS 上的副本独立继续创作，两份项目后续修改互不影响、不自动同步。这不改变每个项目由其所属服务管理正式状态的约束。

用户同时明确调整讨论优先级：重点是代码架构，具体部署体验与复制交互细节留到 ECS 部署试用阶段。四种入口组合、项目可携带与独立复制持续作为架构约束；代码结构所需的身份/权限、保存和任务生命周期现已由后续 ADR 与计划具体化。P8 验证工程内容与失败边界，P10 准备现场试用流程，不提前反复询问按钮或传输形式。
