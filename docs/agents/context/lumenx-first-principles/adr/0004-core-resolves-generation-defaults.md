# Core 统一解析生成默认值，产品差异通过明确预设表达

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

当前模型目录、请求模型和执行路径存在多个默认值来源。用户选择由 Core 按共同规则解析有效生成参数，以模型目录为基础默认；保留用户明确设置的值，产品需要不同的默认组合时使用明确、可见的生成预设，而不在各入口和执行层分别隐式补值。

未选择各功能入口独立维护缺省规则，因为它会使同一缺参请求随入口变化，并增加参数来源、界面显示与实际执行一致性的验证负担。明确预设仍可表达不同产品对成本、速度和质量的选择；代价是需要梳理现有隐式默认及兼容行为。

## 验收方向

- 同一模型、相同明确参数和相同预设，通过不同受支持入口得到一致的有效参数。
- 用户明确提供的有效值保持不变，包括适用字段中的零和 false，不能误判为未设置。
- 入口展示的参数与 Core 解析、实际提交的参数保持一致；产品预设的影响可识别。
- 模型能力校验仍然生效；显式值无效时不能默默换成某个默认值继续执行。

Q7 确定默认值解析责任；随后 Q8 确认下面的参数固定与重试规则。项目/节点设置与旧数据兼容由 2026-10-09 授权内工程补充具体化，见末节；没有批准批量重写历史任务。本记录只维护设计取舍，不登记实现与测试进度。

## Q8 补充：接纳任务时固定有效参数，失败重试沿用

用户选择任务接纳时保存补齐后的完整有效参数，失败重试继续使用这份记录。目录或预设默认值的后续变化不自动改变既有任务；修改参数或采用新默认时发起新的生成，并保留原记录及来源关系。

没有选择在重试时重新补齐原来未设置的字段，因为这会让同一任务因配置更新改变分辨率、时长等执行条件。代价是必须保存实际补齐后的值，不能仅保存用户最初提供的部分参数。现有 Atelier 已有快照和执行尝试标识，可以复用，但执行时仍补缺省的路径需要收敛。

固定参数不保证模型再次生成完全相同的内容，也不绕过当前能力和权限校验。原条件无法执行时应明确反馈，不能静默换模型或参数。此次决定不授权自动重新提交付费生成；Q9 随后确认的查询恢复见 [ADR-0005](0005-recover-submitted-work-without-resubmission.md)。

对应验收：改变目录或预设后，原任务重试的有效参数不变；修改参数或选择新默认会形成新的生成记录；旧记录仍可查询。不能用当前默认伪装成已知历史值。上述是验收要求，是否已有运行证据以执行台账为准。

## 2026-10-09 授权内工程补充

用户要求优劣明确的工程选择由助手决定并记录。以下是对 Q7/Q8 的落实，不反写成用户逐题回答：

- 解析顺序为明确输入 → 明确选定的预设 → catalog；项目/节点已保存设置由产品入口明确投影为输入并保留来源，不再增加隐藏的继承链。
- 快照保存输入角色、有效参数、媒体固定版本/内容身份以及规则与预设版本；供应商的随机策略不伪装成已知实际 seed。提交使用固定媒体内容，重新签名不得偷换内容。
- 旧快照缺失部分保留“未知”标记，不能按当前默认补齐后声称原条件重试；明确的新生成可使用当前条件。只要原任务查询身份充分，缺少生成快照仍不妨碍 Q9 的查询取回。
- Agent 批准绑定预览时的有效意图和成本依据；接纳及提交不能在原批准下改变参数、预设或媒体版本。现有 receipt 重放返回原冻结结果，不重新按新默认解析后再派发。

验收反例包括：批准后默认改变、接纳后同 URL 内容变化、签名过期、原媒体已删除、缺生成快照但有充分查询身份。详情见 [重构计划](../REFACTOR-PLAN.md) 和 [测试映射](../TEST-MATRIX.md)。
