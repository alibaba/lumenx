# Core 统一能力规则与执行契约，功能入口可开放明确的能力子集

规范职责：决定与取舍；`accepted` 不代表实现完成。材料关系见 [README](../README.md)，实施结果见 [台账](../EXECUTION-STATUS.md)。

现有模型目录和供应商适配器已经共享，但部分入口仍存在字段未转发、校验和派发契约不一致。用户选择由 Core 统一参数含义、模型能力校验和供应商执行契约，Studio、Atelier 和 Agent 可以按各自创作流程开放明确的能力子集，无须在每次模型接入时同步开放全部能力。

这个边界保留产品流程与接入节奏的独立性，同时要求已支持的输入完整传递：不支持的输入应明确拒绝，不能接受后静默丢弃、降级或改变含义。模型已支持某能力，不自动等于所有功能入口都已开放；浏览器/桌面是操作入口，与这里的功能入口是两个维度。

## 取舍与约束

未选择“三个功能入口全部实现并验收后，模型能力才算接入完成”，因为这会把不同产品的功能演进绑定在一起。采用能力子集的代价是需要维护各入口的支持范围，并分别验证声明、请求转换与错误反馈；仅有模型目录或 adapter 测试不足以证明入口支持。

该决定不要求共用前端状态、产品任务对象、HTTP 返回形状或候选选择流程，也不单独批准通用任务仓库或数据库替换。默认值与重试由 [ADR-0004](0004-core-resolves-generation-defaults.md)、查询恢复由 [ADR-0005](0005-recover-submitted-work-without-resubmission.md)、共享协议与存储取舍由 [ADR-0006](0006-converge-execution-with-product-owned-state.md) 具体化。任务身份、取消和保存协议按 [现行计划](../REFACTOR-PLAN.md) 实施，不再将它们列作未开始讨论的前置条件。

## 验收方向

- 对入口声明支持的同一模型意图，在共同能力范围内保持参数含义和供应商有效请求一致。
- 对未开放的参考类型或参数组合，在付费提交前明确反馈，不静默忽略输入。
- 某入口可以晚于其他入口开放能力；支持清单和可运行验证要与其实际状态一致。
- 各产品继续拥有自己的创作状态与结果采纳；Agent 执行仍遵循审批与权限约束。

这是已确认的设计边界，不作为测试执行证明；结果见 [执行台账](../EXECUTION-STATUS.md)。原 Core 可行性报告未随公开候选发布；历史议题及映射见 [摘要](../HISTORICAL-FINDINGS.md)。
