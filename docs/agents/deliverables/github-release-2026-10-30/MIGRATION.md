# LumenX Core / Studio / Atelier 迁移说明

本候选从公开基线 `f2a02e23171447c939e7d8e1386b24d17049bbf1` 携带研发快照 `7765f9e816088a88f8489a737ad70eb7211de051` 的最终实现和回归测试。它包含行为与数据合同变化，不能当作只移动文件的重构。当前验证范围见 [发布准备记录](README.md) 与 [候选台账](../../context/lumenx-first-principles/EXECUTION-STATUS.md)。

## 对使用与部署的影响

- Studio、Atelier 与 Playground 共用模型、媒体和执行合同，各自保留项目状态。Atelier 现在位于独立领域，不依赖 Studio 项目。
- 保存与生成请求增加版本、回执和执行身份检查。前端静态文件和后端必须来自同一发布候选；旧客户端缺少版本等字段可能收到 422 或冲突，不能只更新一侧。
- 已提交任务恢复使用原 handle 查询/取回，未知结果保持待确认；不要将“再点一次生成”当作查询恢复。生成完成、技术检查与用户采纳仍是不同事实。
- 一个数据目录只允许一个写进程。旧/新服务不得同时挂载同一数据根，也不要用多 workers 绕过限制。
- 默认本地回环；远程访问需显式访问模式和合格令牌。内部项目 JSON/配置不可通过媒体路由下载。
- 工程导出/导入产生独立副本，保留素材关系并清除在途执行权；不提供两端自动同步，也不是 Studio 与 Atelier 互转。
- 正式桌面路径仍为 `main.py → PyInstaller`。Tauri 是实验入口，其开发运行不能替代正式包验收。

## 升级前

1. 记录当前代码版本、入口和实际数据根。开发模式使用项目 `output/` 与配置；正式桌面通常使用 `~/.lumen-x/`；headless 使用显式 `--data-dir`。以实际启动配置为准。
2. 确认在途生成的原请求/供应商 handle 已保存，正常关闭拥有数据根的服务。保存完整、可恢复的停机备份：配置、项目 JSON、日志、全部媒体和关系文件一起保留。备份包含密钥时按私有数据处理，不上传 GitHub。
3. 用备份的独立副本做迁移验证。不要先对唯一真实项目运行批量迁移、测试收集或清理。
4. 在新依赖环境安装相同候选，构建同版静态页面，运行 [测试门禁](../../context/lumenx-first-principles/TEST-MATRIX.md)；不要复用另一平台的虚拟环境或旧构建。

## 副本验证

先读旧项目、角色/场景/道具、分镜、音频/视频选择和历史，再保存一次受控编辑并重开。验证实际本地媒体解码，导出/独立导入工程包后检查来源未变。对有 handle 的受控任务验证恢复不增加 submit；未知结果不自动新付费。完成保存、媒体、恢复和导出核验之后，再按明确的运维窗口切换真实数据入口。

这份说明没有执行真实用户数据迁移，也不证明所有历史 schema 或自定义插件兼容。具体项目发现的新失败应保留原件并先在副本复现。

## 回退

代码回退不等于数据回退。新版本可能已经写入旧版本不能解释的回执或字段；未验证向后兼容时，不让旧程序直接接管新版本写过的数据。

停止候选服务，保留失败后的数据和日志供诊断，然后使用升级前的完整备份与对应旧程序恢复到独立位置。确认项目和媒体完整后再切换入口。避免覆盖唯一数据副本、删除已付费媒体或重放执行权。

## 本次没有连带合入的工作

旧 Atelier、Wan 3.0 和 Skills 恢复分支保留为独立来源。此候选已有按最终领域重新实现和验证的能力，分支未成为祖先不表示应整支重新合并。额外模型变化或分支独有功能需单独做合同差异、回归与发布判断。
