### 2.2 方案深度分析

#### 2.2.1 jamesyong-42/infinite-canvas - 综合性能最优方案

这个项目是目前GitHub上最成熟、功能最全面的无限画布实现之一。其技术架构与你的需求高度匹配，特别是在Three.js集成和React组件化方面表现出色。

**技术架构优势**：

该方案采用了独特的**双渲染引擎架构**，同时支持DOM和WebGL（React Three Fiber）小部件在同一画布上渲染。这种设计为你的项目带来了巨大优势：

1. **DOM小部件**：用于UI元素、文本编辑、2D图形等轻量级内容
2. **WebGL小部件**：用于3D模型、复杂特效、视频纹理等高性能需求
3. **R3F Canvas**：基于React Three Fiber的WebGL渲染层，与你的Three.js渲染器完美集成

**无限滚动/缩放算法**：

该方案实现了真正的无限空间导航，核心技术包括：
- **视口裁剪（Viewport Culling）**：只渲染可见区域内的实体，大幅减少渲染开销
- **空间索引（Spatial Indexing）**：使用RBush进行空间索引，加速命中测试和视口裁剪
- **响应式断点系统**：根据屏幕空间大小自动调整小部件渲染（micro/compact/normal/expanded/detailed）

在性能测试中，该方案在高端设备上可以稳定达到**120fps**，在移动设备上也能保持60fps的流畅体验。

**交互响应机制**：

该方案提供了完整的跨平台交互支持：
- **桌面端**：鼠标拖拽平移、滚轮缩放、右键上下文菜单
- **移动端**：双指捏合缩放、单指平移、点击选择、双击进入容器
- **手势识别**：内置手势库支持复杂的多点触控交互

**ECS架构的扩展性**：

该方案采用了**实体组件系统（ECS）架构**，这是其最大的技术亮点之一。ECS架构为你的AI视频生成项目带来了以下优势：

1. **高度模块化**：通过自定义组件、标签和系统扩展功能
2. **高效更新**：基于拓扑排序的调度系统，只更新变化的部分
3. **可预测性**：组件化设计使得代码逻辑清晰，易于维护

**与你技术栈的匹配度**：

该方案与你的技术栈几乎完美匹配：
- **React版本**：兼容React 18/19，与你的React 18完全一致
- **Three.js集成**：原生支持Three.js WebGL渲染，包括网格、选择框、WebGL小部件

#### 2.2.3 Codrops Infinite Canvas - 性能优化典范

这个项目提供了基于React Three Fiber的无限画布实现，在性能优化方面有很多值得借鉴的技术。

**分块渲染技术**：

该方案的核心是**分块世界生成（Chunk-based World Generation）**：
- 将空间划分为等大小的立方块
- 只在相机周围保持固定数量的活动块（3×3×3=27个块）
- 块ID使用稳定的字符串，便于React可预测地挂载和卸载块组

**视口裁剪策略**：

该方案实现了智能的视口裁剪和淡入淡出效果：
- 基于距离的淡入淡出：根据块与相机的距离计算透明度
- 深度距离考虑：同时考虑块的网格距离和Z轴深度距离
- 性能优化：当平面完全透明时，将其从渲染中移除，不再写入深度缓冲区

**相机控制和惯性动画**：

该方案实现了物理感十足的相机控制：
- **惯性运动**：收集输入并累积到目标速度，然后将实际速度平滑地趋向目标速度
- **平滑滚动**：将滚动累积到scrollAccum中并逐渐应用
- **基于帧率的积分**：更新basePos而不是直接推动相机，提供可预测的积分点

#### 3.2.3 视频时间线集成

**创建视频轨道组件**

基于ECS架构扩展视频时间线功能：

```typescript
import { defineComponent, defineSystem } from '@jamesyong42/reactive-ecs';

// 定义视频轨道组件
const VideoTrack = defineComponent({
  name: 'VideoTrack',
  schema: {
    videoSources: Array, // 视频源数组
    currentTime: Number, // 当前时间
    duration: Number, // 视频时长
  },
});

// 定义视频播放系统
const VideoPlaybackSystem = defineSystem({
  name: 'VideoPlayback',
  components: [VideoTrack],
  update: (world, deltaTime) => {
    world
      .query(VideoTrack)
      .forEach((entity) => {
        const track = entity.get(VideoTrack);
        
        // 更新视频播放时间
        track.currentTime += deltaTime;
        
        // 循环播放
        if (track.currentTime >= track.duration) {
          track.currentTime = 0;
        }
        
        // 更新视频小部件的时间
        entity.get('VideoWidget')?.updateTime(track.currentTime);
      });
  },
});

// 在引擎中注册组件和系统
engine.registerComponent(VideoTrack);
engine.registerSystem(VideoPlaybackSystem);

// 创建视频轨道实体
function createVideoTrackEntity(engine, sources, position) {
  return engine.spawnEntity({
    type: 'video-track',
    components: {
      [VideoTrack]: {
        videoSources: sources,
        currentTime: 0,
        duration: 10, // 假设视频时长10秒
      },
    },
    position,
    size: { width: 800, height: 60 },
  });
}

// 使用示例
createVideoTrackEntity(engine, ['video1.mp4', 'video2.mp4'], { x: 0, y: -300 });
```

### 3.3 性能优化策略

#### 3.3.1 素材渲染优化

**纹理压缩和优化**：

1. 使用**KTX2或Basis Universal格式**的压缩纹理，相比传统PNG/JPEG可减少约10倍的GPU内存占用
2. 对不同类型的纹理采用不同的压缩策略：
   - 法线贴图：使用UASTC格式，质量更高
   - 漫反射贴图：使用ETC1S格式，文件更小
   - 环境纹理：使用ETC1S格式

**实例化渲染**：

对于重复的素材（如背景元素、装饰性物体），使用实例化渲染：

```typescript
import { InstancedMesh } from 'three';

// 创建1000个重复的树模型
const treeGeometry = new BoxGeometry(1, 3, 1);
const treeMaterial = new MeshStandardMaterial({ color: 0x228B22 });

const treeInstances = new InstancedMesh(treeGeometry, treeMaterial, 1000);

for (let i = 0; i < 1000; i++) {
  const matrix = new Matrix4();
  matrix.setPosition(
    Math.random() * 1000 - 500, // X坐标
    0, // Y坐标
    Math.random() * 1000 - 500  // Z坐标
  );
  treeInstances.setMatrixAt(i, matrix);
}

// 将实例化网格添加到场景
scene.add(treeInstances);
```

实例化渲染可以将1000个独立网格的1000个draw call减少到1个，性能提升可达90%以上。

#### 3.3.2 交互性能优化

**射线投射优化**：

射线投射（Raycasting）是3D交互的基础，但对性能影响较大。以下是优化策略：

1. **限制测试对象**：只对可交互对象进行射线投射测试
2. **使用简单碰撞网格**：为复杂模型创建简化的低多边形碰撞网格
3. **层系统**：使用Three.js的层系统控制射线投射可见性
4. **距离限制**：设置raycaster.far属性限制射线投射距离

```typescript
// 优化的射线投射实现
const raycaster = new Raycaster();
const mouse = new Vector2();
const interactiveObjects = []; // 只包含可交互对象

function onMouseMove(event) {
  // 转换鼠标坐标到NDC
  mouse.x = ((event.clientX - rect.left) / rect.width) * 2 - 1;
  mouse.y = -((event.clientY - rect.top) / rect.height) * 2 + 1;

  raycaster.setFromCamera(mouse, camera);
  
  // 只测试可交互对象
  const intersects = raycaster.intersectObjects(interactiveObjects, true);
  
  // 处理交互逻辑
  if (intersects.length > 0) {
    // 第一个命中的对象
    const hitObject = intersects[0].object;
    // 处理hover效果
    hitObject.material.emissive.setHex(0x333333);
  }
}
```

**手势识别优化**：

对于移动端手势，使用专门的手势库如`@use-gesture/react`，而不是自行实现复杂的触摸事件处理。

#### 3.3.3 内存管理优化

**对象池模式**：

对于频繁创建和销毁的对象（如粒子效果、临时标记等），使用对象池模式：

```typescript
class ObjectPool {
  constructor(initialSize, createFunc) {
    this.pool = [];
    this.createFunc = createFunc;
    
    // 预创建对象
    for (let i = 0; i < initialSize; i++) {
      this.pool.push(this.createFunc());
    }
  }
  
  acquire() {
    return this.pool.length > 0 ? this.pool.pop() : this.createFunc();
  }
  
  release(object) {
    this.pool.push(object);
  }
}

// 使用示例：粒子对象池
const particlePool = new ObjectPool(100, () => {
  return new Particle();
});

// 获取粒子
const particle = particlePool.acquire();
particle.init(position);

// 释放粒子
particlePool.release(particle);
```

**资源清理策略**：

1. 当对象不再使用时，立即调用dispose()方法释放GPU资源
2. 使用WeakRef或FinalizationRegistry跟踪对象生命周期
3. 实现资源引用计数，确保资源在所有引用释放后才被销毁
