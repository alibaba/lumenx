01 · Surface 哲学翻转

面板背景从"黑色叠加层"变为"白色微透层"—— 方向性翻转。

BEFORE
面板内容在黑色 40% 叠加层上
文字可读性受限于深色泥潭
AFTER
面板内容在白色 4% 微透层上
内容获得更多"空气感"和层次
核心差异
Surface 背景方向完全相反：旧方案用 rgba(0,0,0,0.4)（黑色 40% 叠加）使面板"沉入"背景；新方案用 rgba(255,255,255,0.04)（白色 4% 微透）使面板"浮出"背景。虽然两者在暗色主题下看起来相似，但新方案让面板 边界更清晰、层次感更分明，且与内容区形成正确的 figure-ground 关系。
Token旧值新值影响
--color-bg-surface rgba(0,0,0,0.4) → rgba(255,255,255,0.04) 所有面板/卡片/侧边栏
--color-bg-elevated #1a1a1a → #141416 Modal / Dropdown / Elevated Card
--color-bg-inset rgba(255,255,255,0.03) → rgba(255,255,255,0.02) 嵌入区域 (代码块/输入背景)
--color-glass rgba(255,255,255,0.05) → rgba(255,255,255,0.03) Sidebar / Toolbar 辅助层

02 · Backdrop-Blur 大幅减量

Glass 模糊半径从 12px 降至 2-4px，保留层次感但不遮盖内容。

BEFORE
backdrop-filter: blur(12px) — 背后内容完全模糊不可辨
AFTER
backdrop-filter: blur(2px) — 背景隐约可见，层次通过亮度区分
Blur 策略变更
不是去除 glass，而是让 glass "更薄"。旧方案 blur(12px) + 黑叠加 让面板像一块不透明毛玻璃；新方案 blur(2px) + 白微透 让面板像一层薄纱——既保留了 glass language（CLAUDE.md 设计原则），又让内容区域（图片/视频/分镜缩略图）成为真正的视觉主角。

GPU 收益：backdrop-filter blur 半径每减半，GPU 采样成本约降 75%。从 12px → 2px 可节省约 97% 的模糊计算。

PipelineSidebarblur(12px)→blur(2px)步骤导航
ShotCard (expanded)blur(6px)→blur(4px)分镜卡片展开态
Modal overlayblur(8px)→blur(4px)模态叠加层

03 · Border Opacity 精密化

边框从"可见线条"调整为"若隐若现的分界"。

值变更
--color-border-default: rgba(255,255,255,0.10) → rgba(255,255,255,0.08)
--color-border-subtle: rgba(255,255,255,0.05) → rgba(255,255,255,0.04)

差异虽然只有 2% 和 1%，但在大面积面板边界上感知明显——新方案下 chrome 更安静，让内容图片的色彩不被边框线条打断。

04 · Neon / Glow 克制策略

Primary (#646cff) 的发光效果从"无处不在"收敛为"仅在 CTA + Active State"出现。

BEFORE
普通按钮 (有 glow) 次要操作 (有 glow) CTA (更多 glow)
所有按钮都有 glow → 视觉权重平均 → 无主次
AFTER
普通按钮 (无 glow)
普通按钮 次要操作
CTA 方案对比 ▾
原版 (纯色) ✓ 最终方案 (三段渐变) 备选 (玻璃内光)
三种 CTA 风格对比：原版纯实底 vs 渐变+微透 vs 毛玻璃+内侧高光
Glow 使用规则 (新)
允许 glow 的场景（仅限）：
1. Primary CTA 按钮 (hover 态 box-shadow: 0 0 16px rgba(100,108,255,0.3))
2. Sidebar active indicator (2px 竖线 + 微弱 shadow)
3. 异步任务 in-flight 状态 (processing badge pulse)
4. Starred/Golden selection border (status-starred-solid)

移除 glow 的场景：所有 glass-button 的 box-shadow、BorderGlow 在非 CTA 元素上的使用、Tooltip 的渐变 glow、非 active 导航项。

AFTER

全新模式说明
现有代码中不存在此模式。新 StepHeader 包含 4 层信息：
1. Ghost Number — 64px 半透明数字水印 (opacity 0.03)，提供空间锚点
2. Eyebrow — Mono 9.5px 大写，格式: "STEP {N} · {CATEGORY}"
3. Title — Space Grotesk 15px semibold，当前步骤名称
4. Subtitle — 12px muted，实时状态摘要 (shot count / completion)

设计意图：给用户强烈的"我在第几步"空间感知，同时 subtitle 减少需要切换到 overview 查看进度的次数。

08 · FieldTagChip 实体类型色彩系统 NEW

Prompt 区域的实体标签从"纯文字"变为"按角色/场景/道具三类着色的 chip"。

BEFORE
Prompt: 星莲 站在天台上，城市霓虹灯光映照。手持道具：魔法书。
纯文本，无语义标注可视化
AFTER
Prompt entities:
@星莲 #天台夜景 #城市霓虹 $魔法书
@ = character · # = scene · $ = prop → 一目了然
全新模式说明
FieldTagChip 存在于现有代码中（storyboard-r2v/FieldTagChip.tsx），但没有按实体类型区分颜色。新方案定义三种语义变体：
1. Character (蓝紫) — 与 --seed-primary 同色系
2. Scene (粉红) — 与 --seed-accent 同色系
3. Prop (金橙) — 与 status-starred 同色系

用户在编辑 prompt 时可以一眼辨别"哪些是角色引用，哪些是场景描述，哪些是道具指令"，大幅提升编辑效率。

排版策略

差异全景总结

Token 值变更 (微调)

Surface 哲学翻转 (rgba方向) · Blur 减量 (12 → 2px) · Border opacity (-2%) · Elevated 色值 (#1a → #14) · Glass 浓度 (-2%)

全新模式 (现有代码不存在)

StepHeader 4层结构 · ProgressRail 进度轨道 · Ghost Number 水印 · Entity-typed Chips (3色) · Candidates 4列网格 + Starred 金色选中

策略性移除 / 克制

非 CTA 的 glow/shadow · 按钮 backdrop-filter · BorderGlow 在静态元素上的使用 · Sidebar bg-fill active · 不统一的 chrome 排版

架构性新增 (不可见但关键)

Seed token 层 (6变量) · Component token 层 (30+变量) · Primitive 灰阶 (7级) · Surface 5级语义 · Motion token 连接 · 3-layer 推导架构

为什么"看不出来"？

"克制电影感"方向的核心就是不做革命性外观变更。色板相同、字体相同、布局骨架相同——改变发生在"看不见但能感受到"的层面：surface 的呼吸感、chrome 的安静程度、注意力流向内容的自然度。这些差异在静态截图中很难察觉，需要在交互中（hover / transition / focus flow）才能充分体验。

本文档将这些"感受层"差异提升为可视化的具体 token 值变更 + AB 对比渲染，让产品决策者可以在审批前明确"改了什么"以及"为什么要改"。
