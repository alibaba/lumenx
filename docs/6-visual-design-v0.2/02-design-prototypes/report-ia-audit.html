路由入口 (SPA)

Studio 是一个单页应用（SPA），所有视图由 page.tsx (35KB) 通过 hash router 切换。没有利用 Next.js App Router 的文件系统路由能力——这意味着无法享受自动 code-splitting、metadata API、loading.tsx 等框架特性。

SPA 路由影响分析 (v1.1 新增)

首屏全量加载 ~2.4MB：用户打开 Workspace 首页时，Script / ArtDirection / Cast / StoryboardR2V / Assembly / Library / Settings 所有模块 JS 一次性下载。新增 Playground (12 组件) 将进一步增加首屏负担。

丢失的框架能力：①自动 code-splitting（按路由懒加载）②metadata API（路由级 title/OG 标签）③loading.tsx / error.tsx（路由级骨架屏和错误边界）④Streaming SSR（分段流式首屏输出）⑤React Suspense 边界自动绑定路由。

3 级改进路径：

Level 1 — Dynamic Import (最小侵入, 2-3d)：保留 hash router，每个模块用 React.lazy() + <Suspense> 包裹。首屏只加载 Workspace (~200-400KB)，其余模块点到时才下载。

Level 2 — Playground 作为 App Router 试点 (推荐, 3-5d)：Playground 是全新模块无历史包袱，以 app/studio/playground/page.tsx 独立成 App Router route。验证后逐步迁移其它模块。

Level 3 — 全量 App Router 迁移 (终极, 2-3w)：每个 Pipeline step 独立 route segment，享受全部框架特性。配合 Phase 3 执行。

5 导航与路由体验

5.1 当前路由策略问题

  1. 无 URL deep-link 支持：hash 路由下，Pipeline 步骤 (Script → R2V → Assembly) 无独立 URL。用户无法分享 "项目X 的分镜R2V" 链接。
  2. 无 browser history 友好跳转：浏览器后退/前进按钮行为不可预期（hash 变化 vs 组件内 state 跳转混合）。
  3. 无 code-splitting：所有 Pipeline 模块打包进同一 chunk。StoryboardR2V 23 文件 + Three.js Canvas 全量首屏加载。新增 Playground 12 文件将进一步加剧负担。
  4. Shell 状态不连续：从 Workspace → Project 时 AppShell unmount，GlobalSidebar 消失并重新挂载为 PipelineSidebar，产生布局闪烁。
  5. Playground 路由归属问题 (NEW)：Playground 作为非 Project 模块，应走 AppShell 路径 (与 Workspace/Library/Settings 同级)。当前 hash router 下需在 page.tsx 新增 #/playground 分支——进一步膨胀已 35KB 的文件。

5.2 建议改进方向

提案 (v1.1 更新)

推荐路径：以 Playground 为 App Router 试点。

Playground 是全新模块、无历史包袱，天然适合第一个迁移至 app/studio/playground/page.tsx 的 App Router route。可验证：①文件系统路由 ②自动 code-splitting ③独立 loading.tsx 骨架屏 ④独立 error.tsx 错误边界 ⑤metadata API。成功后逐步迁移 Library → Settings → Pipeline。

保守替代方案：至少对所有 hash 分支使用 React.lazy() + <Suspense> 包裹，实现按需加载。预计可减少首屏加载体积 40-60% (从 ~2.4MB 降至 ~800KB-1MB)。

缺陷影响建议
无 seed 层品牌色 #646cff 硬编码在多处 Tailwind 类中，无法一处修改全站更新引入 --seed-primary / --seed-accent / --seed-bg / --seed-fg 基础层

审计结论 (v1.1 更新)

Studio 前端已具备功能完整度，但在视觉层次（Glass 过重 / Surface 混用 / CTA 扁平→已解决）、架构颗粒度（单文件过大 / 模块平铺 / SPA 路由瓶颈）和token 治理（缺 seed 层 / 组件层 / motion 连接→部分已建立）三方面存在系统性技术债。

新增 Playground 模块是路由架构改进的最佳契机：作为无历史包袱的全新功能，它天然适合 App Router 试点（Level 2 方案），既避免 page.tsx 继续膨胀，又为后续模块迁移积累经验。建议按 P0→P1→P2 分 3 个 Phase 清偿，详见《重构方案与里程碑路线》。
