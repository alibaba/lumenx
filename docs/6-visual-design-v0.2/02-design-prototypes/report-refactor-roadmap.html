重构方案与里程碑路线

从 Token 注入到 Pipeline 全量迁移的 4 阶段渐进式重构计划。每阶段可独立交付价值，无需"大爆炸"重写。

日期 2026-06-06 版本 v1.0 总工期估算 6-8 周 前提 不影响 R2V Phase 1 稳定化

1 重构战略原则

  1. 渐进不断裂 — 每个 Phase 结束时产出可部署、功能等价的中间态。避免 "refactor branch hell"。
  2. Token-first — 先注入 seed→semantic→component 3-layer token 系统，后续视觉迁移变为"换 token 值"而非"改 class"。
  3. Content-is-King 验证 — 每次视觉调整通过"截图 AB 比对"确认内容区域视觉权重 > chrome 区域。
  4. Atelier 不干涉 — 严守 CLAUDE.md 约束：Studio 重构不引入 Atelier 依赖，仅通过 seed token 命名约定为未来对齐留接口。
  5. Zero-regression on R2V — Phase 1 不重构 StoryboardR2V 功能代码，仅做 token 替换和 Glass 减量。

Phase 0 — Token Foundation 1.5 ~ 2 WEEKS
风险 LOW功能影响 ZERO (纯加法)前置依赖 NONE

注入 3-layer token 系统（seed → semantic → component），建立视觉契约。现有样式不动，新 token 作为"叠加层"存在。

交付物

design-system.css — seed + semantic + component 3 层 CSS vars (已完成草稿)
DESIGN.md — 完整 DS 规范文档 (已完成草稿)
globals-v2.css — 在现有 globals.css 基础上注入 seed 层 + 更新 semantic 值
tailwind.config.v2.ts — 新增 seed-* / component token 引用，保留全部旧 key
_showcase.html — 组件 token 效果展示（已完成）
Surface Hierarchy 文档 — 5 级 surface 定义 + 使用规则

技术方案

  1. 创建 design-tokens/ 目录，放置 seed.css、semantic.css、components.css
  2. 在 globals.css 顶部 @import seed 层；semantic 层覆写现有 CSS var 值（向后兼容）
  3. Tailwind config 中新增 seed namespace，旧 token key 保留 + 新增 component 引用 var(--button-bg) 形式
  4. 确保所有现有 Tailwind 类名仍可工作（旧 semantic 变量值只是从新 seed 推导出来）
  5. 运行全量 E2E 截图对比：视觉零差异 = 注入成功

验收标准

  • ✅ 修改 --seed-primary 一处 → 全站所有 primary 用色同步更新
  • ✅ 修改 --button-bg → 所有按钮背景同步更新，不影响 Card/Input
  • ✅ 视觉回归测试 0 diff（像素级一致）
  • ✅ Lighthouse Performance 无退步

Shell Migration Guide — 开发者迁移文档

技术方案

  1. 新建 layout/UnifiedShell.tsx：固定 sidebar (w-56) + 动态 content area
  2. Sidebar 内部根据 route 自动切换"全局导航"模式 (workspace/library/settings) 和"Pipeline 步骤"模式 (project context)
  3. 消除 page.tsx 内 hash routing：拆为 app/(workspace)/page.tsx + app/project/[id]/page.tsx + app/project/[id]/[step]/page.tsx
  4. 每个 Pipeline step 成为独立 lazy segment → 自动 code-splitting
  5. Glass 减量：sidebar backdrop-blur: 2px, bg: rgba(255,255,255,0.04), border: rgba(255,255,255,0.08)
  6. Transition: sidebar 展开/收起用 CSS transition (transform + opacity)，不触发 layout reflow

6 需产品决策的事项

决策清单

D1. Legacy 6-step pipeline 是否在本轮废弃？还是仅视觉统一但保留功能分支？

D2. CreativeCanvas 背景动画：保留（优化性能）还是替换为静态渐变？

D3. 路由迁移策略：Next.js App Router (最彻底) vs React Router v6 (风险更低) vs 仅重构 hash 结构 (最小变动)？

D4. Storybook 是独立部署还是嵌入 dev server？是否对外可见？

D5. 是否为 Atelier 预留 dark/light theme 切换能力，还是 Studio 永远 dark-first？

7 结语

本方案核心理念：Token 是基础设施，视觉是 Token 的结果。Phase 0 建立 token 系统后，后续所有视觉调整本质上只是"调参"——改 --seed-primary 的值、改 --card-border 的 opacity、改 --duration-base 的毫秒数。这使得设计迭代从"改 79 个文件的 class"变为"改 1 个 CSS 变量文件"。

6-8 周工期包含充分缓冲。如果 Phase 0 验证顺利（预计大概率，因为是纯加法），可以考虑 Phase 0 + Phase 1 合并为 3 周冲刺。
